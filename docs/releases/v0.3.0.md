# ChatSheet v0.3.0

`v0.3.0` 新增合并与取消合并单元格工具、根目录的双击式安装器，把面板“适配”改为与模型操作同款的操作卡片，并把排队中的输入从对话流移到输入区上方的排队条。版本号从 `0.2.1` 跳到 `0.3.0`，是因为前两项扩大了加载项的能力边界，而不只是修正既有行为。

## 新增：合并与取消合并单元格

工具清单里补上 `merge_cells` 与 `unmerge_cells`。此前用户要求合并单元格时，模型会准确地回答自己做不到——那个回答没错，错的是清单：合并是 Excel 排版最常用的操作之一，做标题行几乎绕不开。

- `merge_cells` 接受 `range`、`sheet`、`across`（为真时逐行分别合并）以及可选的水平与垂直对齐。对齐是同一次调用的参数而不是另一个工具，因为功能区上“合并后居中”本就是一个按钮，分成两次会留下两条撤销记录、让用户点一次撤两次。不指定对齐时不动原有对齐。
- 两个工具的风险级别都是 `Write`，因此默认逐项审批，审批卡里显示影响范围。

合并是所有写操作里唯一会**静默丢数据**的一个：宿主只保留左上角的值，其余一概丢弃，事后没有迹象可查。围绕这一点做了三件事：

- 合并前整片读一次，数出会被丢弃的非空单元格个数，作为 `discarded_values` 回报给模型，供它判断是否该先问用户；工具说明也要求合并前先读一遍范围。同时回报实际的合并区域，因为宿主可能把范围外已有的合并一并吞进来。
- 撤销会把被丢弃的值逐格写回，而不只是把格子拆开。因此合并受 5,000 单元格上限约束，超限时**拒绝执行**并报 `RANGE_TOO_LARGE`——`fit_range` 超限时最坏是版面变了、看得见也改得回来，合并最坏是值没了、且看不出少了什么。
- 在已有合并的版面上再合一次，撤销会把原来那些合并区域装回去，而不是整片拆平成用户从未见过的样子。

取消合并不丢数据，快照只记合并状态。合并期间会临时关闭宿主的“仅保留左上角的值”确认框：加载项跑在 Excel UI 线程上，那个框会把 Excel 连同面板一起冻住，而用户的许可已由审批卡收过一次。

## 新增：双击 `install.bat` 打开安装菜单

此前安装的唯一入口是一行带 `-ExecutionPolicy Bypass` 的 PowerShell 命令，而 `.ps1` 双击是打不开的。发行包和源码检出的根目录现在都有 `install.bat`，双击打开菜单：

```text
  当前状态：已安装 0.3.0.0
  运行模式：预构建发行包（不需要 .NET SDK）
  安装位置：C:\Users\<你>\AppData\Local\ChatSheet\app

  [1] 安装或更新    覆盖安装并注册，Excel 需重启才生效
  [2] 卸载          反注册并删除安装目录，保留日志与设置
  [3] 诊断          检查运行时、COM 注册、宿主登记与日志
  [4] 退出
```

菜单先报三件事再给选项：装的是哪个版本、当前是源码检出还是预构建发行包（决定“安装”会不会先 `dotnet build`）、装到哪里去。授权在菜单启动时提一次，之后每个操作都在同一个窗口里跑完，操作结束后回到菜单；输入不是选项的值会提示无效并重新给出选项。

`install.ps1` 一行没改，仍是真正干活的脚本；原有命令行用法完全保留，与菜单等价。

## 变更：面板“适配”改用操作卡片并标出来源

“适配”此前呈现为一条提示胶囊，与模型发起的操作两种样式。要回答的问题其实完全一样——改了哪个范围、影响多少格、能不能撤销——却要在两处找同一种信息；而真正值得区分的“谁发起的”反倒没被表达出来。

现在两者用同一张卡片，区别只剩来源：手动操作在摘要行上带“手动”标记，边条换主色。标记是主要手段，颜色是辅助——颜色说不出区别在哪，高对比模式或色觉障碍下也可能看不出来。

卡片在点下按钮时就上屏并显示“执行中…”，结果到了原地填充；整表适配可能跑一两分钟，这段时间摘要行本身就是进度反馈。宿主拒绝或调用抛异常也填回同一张卡，不会留下一张永远停在“执行中…”的卡片。适配仍然不进对话历史。

## 变更：排队条移到输入区上方，限高三条并可滑动

排队中的输入不再作为虚线气泡进入对话流。对话流记录的是已经发生的事，还没发出去的内容混在里面读起来像已经处理过；而且它会随对话流滚动被顶出可视区，用户此时最想确认的恰恰是“刚排的还在不在、排第几”。

- 排队项显示在输入区上方、与“本轮 xx 入 / xx 出”并排的排队条上，越早排的越靠上，队首贴着输入框——最下面那条就是马上要发生的。队列为空时整条收起。
- 排队条高度封在三条（60px），多出来的靠竖向滑动看，每次队列变化后视口都回到队首。实测排到 12 条时对话区不再被压掉 249px。
- 轮到某条时它才进对话流，因此同一条同一时刻只出现在一处。
- 取消一条或停止清空队列时，排队项直接消失，不再往对话流插一条划掉的气泡。代价是**取消掉的那段文字不再有地方可取**：完整正文在悬停说明里，取消后一并消失。停止仍会告知取消了多少条。

队列语义没有变化：面板侧 FIFO、单实例轮转、附件在入队时绑定、停止与新会话清空队列。审批策略也没有变化——队列中的每条消息在执行时仍按当前审批设置逐项征求同意。

详细实现记录：[合并单元格工具](../changes/2026-08-25-cell-merge-tools.md)、[双击式安装器](../changes/2026-08-25-menu-installer.md)、[适配改用操作卡片](../changes/2026-08-25-panel-operation-cards.md)、[排队条移到本轮用量旁](../changes/2026-08-25-queue-strip-beside-usage.md)、[排队条限高并可滑动](../changes/2026-08-25-queue-strip-scroll-cap.md)。

## 升级方式

`v0.2.1` 及更早版本的用户按 [Windows 发行包安装说明](../windows-release-install.md) 的升级步骤执行即可：关闭 Excel，解压新包，双击根目录的 `install.bat` 并输入 `1` 覆盖安装。设置、密钥与面板宽度保存在 `%LOCALAPPDATA%\ChatSheet\` 下，不会被覆盖安装清除。

Excel 加载的是安装目录中的加载项程序集，因此必须完成安装并重启 Excel，上述改动才会生效。

## 安全与兼容性边界

与 `v0.2.1` 一致，本版没有扩大权限或网络边界：

- 仅支持 Windows 桌面版 Microsoft Excel；不支持 WPS 表格、Excel 网页版或 Excel for Mac。
- 需要 .NET Framework 4.8、Microsoft Edge WebView2 Runtime 和 UAC 管理员授权。管理员权限用于机器级托管 COM 注册，Excel 加载项登记仍只影响当前用户。`install.bat` 在启动时请求这一次授权，它不改变所需权限本身。
- ZIP 不是 MSI/EXE，也没有代码签名、自动更新或静默安装功能。下载后请先验证 SHA-256。
- 模型请求由加载项进程发送到你配置的服务商；提示词、工作簿结构、读取结果以及主动附加的图片和文本文件内容可能离开本机。
- 合并单元格会丢弃左上角以外的值。工具会在合并前统计将被丢弃的非空单元格数并回报给模型，撤销也能把这些值找回，但这不替代人工复核：默认逐项审批仍是建议设置，重要工作簿仍应先备份。

## 安装

1. 在 [GitHub Release](https://github.com/aEboli/Office-helper/releases/tag/v0.3.0) 下载 ZIP 与 `.sha256` 文件。
2. 比较 ZIP 的 SHA-256 与 sidecar 内容。
3. 解压 ZIP，关闭 Excel，双击解压根目录下的 `install.bat`，输入 `1` 回车。等价的命令行写法：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -Action install
   ```

4. 接受 UAC 提示，重新打开 Excel，再在 **ChatSheet** 选项卡中打开面板。

发行包安装不需要 .NET SDK 或 Node.js；从源码构建仍需要 .NET SDK。Release 页面提供的 ZIP 和 sidecar 将与 `v0.3.0` 标签指向的提交一起核验。
