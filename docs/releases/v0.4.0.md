# ChatSheet v0.4.0

`v0.4.0` 让加载项按模型**实际具备的能力**发请求：不支持原生工具调用的模型改用文本指令协议，照样能读写工作簿；没有视觉能力的模型可以经中转模型「看」图，或去掉图片继续并明确告知。此外，点面板上的「适配」图标现在直接按当前对齐排版，不必再在浮层里点第二下。版本号从 `0.3.0` 走到 `0.4.0`，是因为前者让此前完全不可用的一批模型可用，扩大了能力边界，而不只是修正既有行为。

## 新增：模型不支持工具调用时改用文本指令协议

此前加载项对每个模型都发同一种请求：一律附带 17 个工具的函数声明（约 2100 token）。不具备工具能力的模型有两种表现，都不好收场——服务端以 400 拒绝，整轮直接失败；或者服务端接受但模型一个调用都不发，只回一句「我无法访问你的表格」。

现在按「连接 + 模型」建能力档案，三档按需降级：

```text
原生函数声明  →  文本指令协议  →  顾问模式
```

**文本指令协议**不发 `tools` 字段，改为把工具清单以紧凑签名写进系统提示，约定模型用围栏块发起调用：

````text
```chatsheet:tool
{"tool": "write_values", "args": {"range": "A1:B1", "values": [["名称", "数量"]]}}
```
````

清单写成 `write_values(range, values, sheet?)` 加一行说明，约 700 token，是原生声明的三分之一——弱模型读不动嵌套 JSON Schema，而紧凑签名把「必填/可选」直接标在参数名上。

解析出的调用走**与原生调用完全相同的链路**：同一套审批策略、同一套参数校验、同一套单元格上限、同一条撤销记录、同一张操作卡片。文本协议不提供任何原生调用拿不到的东西，也绕不过任何检查——这是它敢自动启用的前提。指令块经一道流式闸门拦在对话气泡之外，用户看到的仍是操作卡片。

进入文本协议有两条路：

- 服务端以 4xx 拒绝，且错误文本提到 `tools`、`tool_choice`、`function calling` 这类协议字段名。
- 模型收下声明后零调用，且正文同时出现「做不到」与「表格」两层意思。这条针对的正是服务端不报错的情形——那时唯一的信号就是这句推辞。它加了三道闸：只在自动探测下生效、每个连接+模型只试一次、必须同时命中两层意思。模型拒绝越权请求时也会说「我不能」，那是对的，不该触发降级。

两条路都在原地重跑当前那一步，不消耗单轮步数上限——上一次尝试没有任何进展。

**顾问模式**在文本协议也走不通时启用（连续两步既无指令块也无工具调用）：不带工具，且系统提示会**收回**「你已经连上工作簿」这句话。这一条是为了防最坏情况——一个既动不了手、又被反复告知自己有读写权限的模型，会编造出「我已经帮你填好了」。

## 新增：模型没有视觉能力时的两条回退

`ImageSupport` 此前对所有协议一律放行图片，注释里写着「具体模型可能不支持——那只能等服务端报错」。于是用户贴一张截图，得到的是一条原始 400。

现在服务端因图片拒绝时记下该模型没有视觉能力，然后：

- **配了「视觉中转模型」**：每张图单独发给它，沿用同一套接口地址与密钥、只换模型名。转述提示词限定在表格用途上——结构、表头、可见数值、报错原文；泛泛地「描述这张图」只会得到「一张电子表格的截图」这种无用回答。描述以文本替换原图进入上下文，并注明这是转写、涉及具体数值要调用工具读表核对，避免模型把有损的描述当事实写进单元格。描述按图缓存，一轮跑几十步也不会重复付费。
- **没配**：去掉图片重发这一轮，并告知模型「用户附了图但你看不到，不要假装看过」。

两条路都会在对话流里留一条说明。图片**不会被静默丢弃**——用户以为模型看过自己的截图，就会相信一个从未基于它的回答，这是这条链路最危险的失败方式。

中转模型自己失败时退回「去图续跑」并说明原因，不让整轮失败。

## 新增：设置页可手动指定

「高级参数」里新增两项：

| 设置项 | 默认 | 何时需要动它 |
| --- | --- | --- |
| 工具调用方式 | 自动探测 | 服务端既不报错、也不真的调用工具时。这类网关会把 `tools` 声明静默丢掉，探测无从触发，此时直接选「文本指令」 |
| 视觉中转模型 | 空（不启用） | 主模型看不了图，但同一服务商下有带视觉的型号时 |

改动工具调用方式会作废已探测的结果，否则从「文本指令」改回「自动探测」等于这个选项没生效。

探测结果按「连接 + 模型」记在本次面板会话内，**不写入设置文件**——网关补上支持后重开面板即可重新探测，不需要用户手动清理任何东西。

## 修正：重试与降级的计数不再跨次累加

两处过程计数此前会带着历史继续数：

- 文本协议下「连续几步没有指令块」的计数挂在能力档案上，而档案跨轮存活。后果是：一轮寒暄记一笔，下一轮再一句寒暄就到阈值——于是把一个一直都能干活的模型误判成「不会用指令块」，永久降级成顾问模式。现在这个计数按轮归零，且任何一步有进展就立刻归零。
- 接口调用的重试计数本就是每次请求的局部量，成功即归零，但此前没有任何测试锁住这一点。现在补了一组用真实 TCP 服务驱动的用例：同一个客户端连发两次请求，第一次用掉的重试次数不占用第二次的预算，第二次重新从「第 1 次」数起。

## 改进：点「适配」直接按当前对齐排版

按钮上写着「适配」，此前点下去却什么也没排——只展开一张三选一的浮层，还得再点一项才动手。于是默认对齐形同不存在，而连续排好几张表时，每张都要重复「点开浮层 → 点同一项」，后一次点击不携带任何新信息。

```text
点图标        →  按当前对齐（默认居中）直接适配
悬停图标      →  浮层展开，用来换对齐方式
浮层里选一项  →  记住这一种，并立刻按它适配
```

选过的对齐记在本机，连续排版时沿用。垂直方向固定居中，不给选项——行变高后文字贴顶是要解决的问题本身。

详细实现记录：[按模型能力回退](../changes/2026-08-26-model-capability-fallback.md)、[点适配直接按当前对齐](../changes/2026-08-26-fit-click-applies-current-alignment.md)。

## 升级方式

`v0.3.0` 及更早版本的用户按 [Windows 发行包安装说明](../windows-release-install.md) 的升级步骤执行即可：关闭 Excel，解压新包，双击根目录的 `install.bat` 并输入 `1` 覆盖安装。设置、密钥与面板宽度保存在 `%LOCALAPPDATA%\ChatSheet\` 下，不会被覆盖安装清除。

新增的两个设置项有默认值（自动探测、不启用中转），升级后不需要做任何配置改动；原有行为在支持工具调用的模型上**逐字不变**——能力探测只在请求被拒或模型推辞之后才介入。

Excel 加载的是安装目录中的加载项程序集，因此必须完成安装并重启 Excel，上述改动才会生效。

## 安全与兼容性边界

与 `v0.3.0` 一致，本版没有扩大权限或网络边界：

- 仅支持 Windows 桌面版 Microsoft Excel；不支持 WPS 表格、Excel 网页版或 Excel for Mac。
- 需要 .NET Framework 4.8、Microsoft Edge WebView2 Runtime 和 UAC 管理员授权。管理员权限用于机器级托管 COM 注册，Excel 加载项登记仍只影响当前用户。
- ZIP 不是 MSI/EXE，也没有代码签名、自动更新或静默安装功能。下载后请先验证 SHA-256。
- 模型请求由加载项进程发送到你配置的服务商；提示词、工作簿结构、读取结果以及主动附加的图片和文本文件内容可能离开本机。
- **文本指令协议不放宽任何权限。** 它解析出的调用与原生工具调用经过同一条执行链路：同一套审批策略、同一套单元格上限、同一条撤销记录。它改变的只是「调用怎么传达给加载项」，不是「加载项允许做什么」。
- **视觉中转会把图片发给你指定的那个模型。** 该请求沿用当前接口地址与密钥，只替换模型名。不配置这一项就不会发生任何额外请求。
- 能力探测结果只存在于面板进程内存中，不写入设置文件，也不包含密钥。

## 安装

1. 在 [GitHub Release](https://github.com/aEboli/Office-helper/releases/tag/v0.4.0) 下载 ZIP 与 `.sha256` 文件。
2. 比较 ZIP 的 SHA-256 与 sidecar 内容。
3. 解压 ZIP，关闭 Excel，双击解压根目录下的 `install.bat`，输入 `1` 回车。等价的命令行写法：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -Action install
   ```

4. 接受 UAC 提示，重新打开 Excel，再在 **ChatSheet** 选项卡中打开面板。

发行包安装不需要 .NET SDK 或 Node.js；从源码构建仍需要 .NET SDK。Release 页面提供的 ZIP 和 sidecar 将与 `v0.4.0` 标签指向的提交一起核验。
