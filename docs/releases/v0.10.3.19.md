# v0.10.3.19 文本协议工具调用配平修复

修复文本指令协议下助手历史消息同时带着正文指令块和一份原生 `tool_calls`，导致下一步请求「有调用、没结果」而整轮失败的问题。

## 现象

- 面板在第二次请求时报 `接口返回 502 Bad Gateway：No tool output found for function call fc_txt1-739998.`，五次重试后整轮失败。
- 换模型（`deepseek-v4.1-flash` → `gpt-6-luna`）、换协议（chat-completions → responses）都不恢复。
- 另一些网关回 400：`An assistant message with 'tool_calls' must be followed by tool messages responding to each 'tool_call_id'`。
- 错误里的 `fc_txt1-739998` 就是文本协议合成调用标识 `txt1-739998` 加上网关前缀 `fc_`。

## 原因

文本形态解析出的调用被同时写进助手消息的 `tool_calls` 和正文的指令块，而工具结果按协议只能以 user 消息回灌。服务端要求带 `tool_calls` 的助手消息紧跟对应的 tool 结果，于是整轮被拒；这条坏消息留在会话历史里，之后每一轮都带着它重发，一次故障把后续所有轮次拖死。

## 修复

- 文本形态不再把合成调用挂进助手历史：正文里的指令块已经足够让模型看到自己发过什么。
- 每轮开始先修一次历史，摘掉配不上的调用与结果，坏结构不再跨轮累积。
- 请求出口统一配平（OpenAI Chat Completions、OpenAI Responses、Anthropic、Gemini 四种协议）：调用缺结果时只留正文，结果缺调用时整条丢弃，Anthropic 下不产生空正文块。
- 上下文裁剪即使只丢了工具结果，也不会把不成对的结构送到服务端。
