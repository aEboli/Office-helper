# v0.10.3.20 请求配平、参数校验与验证链路加固

修复三处在真实对话里能稳定复现的缺陷（孤儿工具结果、参数校验比执行层更严、`excel_object` 先打扰用户再报缺参），并把版本号、文档与仓库卫生重新对齐，最后收敛成一条命令跑完全部回归。

## 现象

- 一轮里助手发出两个调用（例如 `call_1`、`call_2`），结果都配上了，紧跟其后又多出一条不属于任何调用的 `role:"tool"` 消息。下一次请求整轮被拒：`An assistant message with 'tool_calls' must be followed by tool messages responding to each 'tool_call_id'`。清空会话重问就好，说明坏结构留在了历史里。
- 模型把 `read_range` 的 `offset` 写成字符串 `"0"`，或把 `include_formulas` 写成 `null`（等价于未提供），工具在参数校验阶段直接返回 `ARG_INVALID`；而执行层本来能把这两种形态正确读出来。模型换个写法重发一次又能过，白烧一轮。
- `excel_object` 漏写 `root` 时，面板先弹「选哪一层」让用户点一次，点完才提示缺参。用户白点一次，真正的问题在调用本身。
- README 顶部写「下载公开版 v0.10.3.17」，正文写「当前源码版本 0.10.3.19」，`docs/windows-release-install.md` 通篇是 0.10.3.17。源码、下载页和安装指南三处版本互相打架。
- `PaneHarness.exe --workbuddy-ui` 必然失败：`WorkBuddyUiTests.cs` 里把标题栏版本硬编码成 `0.10.3.13`，与实际安装的版本无关，每升一次版本就红一次。
- 仓库根出现 `%SystemDrive%/`、`ChatSheet/component-staging/install.lock`、`NUL`、`.claude/agents/ttt.agent.md` 等运行期残留和个人配置，都没有被忽略。
- 验证步骤散落在 README 和多份 `scripts/verify-*.ps1` 里，没有一条命令能跑完全部回归，也没有统一口径的「通过 N，失败 M」。

## 原因

- `MessageRepair` 把「本次调用的结果全部配上」当成可以直接整段放行：该分支直接把连续的一段 `role:"tool"` 消息全部 `AddRange`，其中混着的孤儿结果没人检查。而部分配对的分支是逐条按 `matched[]` 放的，两条分支行为不一致，问题只在「全配对 + 多一条」这个组合下暴露。
- `ValidateArguments` 按 `JTokenType` 严格比对 JSON 类型，比执行层的读取逻辑更严：执行层对 `offset` 走 `Value<long?>`、对布尔参数走 `OptionalBool`，都能接受可无损转换的字符串和 `null`；校验层却按原始 token 类型直接判死。
- `excel_object` 的 `root` 缺失要做交互补全，这段交互写在完整校验之前，于是「非交互就能判定的必填/类型问题」被排到了用户点击之后。
- 版本号散落在四个地方（两个 `csproj`、`index.html` 的 `data-version` 与文本、`version.test.mjs` 的三处字面量），发布时只改了代码没改文档，下载页与安装指南因此停在 0.10.3.17。
- PaneHarness 的 UI 断言把版本当常量写死，它验证的其实是「这台机器上装的是不是当年那个版本」，而不是「标题栏显示的版本和页面声明一致」。
- 运行期残留由 PowerShell 把字面量 `%SystemDrive%` 当相对路径、`>NUL` 重定向和相对路径锁文件共同产生，`.gitignore` 没有对应的规则。
- 每份 `verify-*.ps1` 各验一件事，但没有一个总入口；失败清单要人工比对。

## 修复

- **MessageRepair 全配对分支不再整段放行**：与部分配对分支统一成逐条按 `matched[]` 处理 —— 配上的结果放行，未配上的计入 `DroppedResults`。两条分支从此只有「保留多少个调用」的差别，不再有「保留哪些结果」的差别。
- **参数校验对齐执行层的宽容度**：非必填参数值为 `null` 一律视为未提供、跳过类型检查（必填里的 `null`/空白字符串仍报 `ARG_MISSING`）；`integer`/`number`/`boolean` 接受可无损转换的字符串（`"0"`、`"12.5"`、`"true"`/`"false"`），转换失败才报 `ARG_INVALID`；数组与对象仍严格。新增带跳过集合的 `ValidateArguments` 重载供 `excel_object` 使用。同时把 `read_range.include_formulas`、`merge_cells.across`、`sort_range.ascending`、`sort_range.has_header`、`create_table.has_header` 的 schema 改成 `["boolean","null"]`，与既有 `bold`/`italic`/`font_size`/`wrap_text` 的写法保持一致。
- **`excel_object` 先校验、再交互**：把不依赖用户的必填/类型校验（跳过 `root`）提到交互之前，模型漏写 `path` 之类的参数立刻收到 `ARG_MISSING`，不再让用户先点一次；`root` 补全后、写回 `args["root"]` 时再做一次完整校验。其余工具的校验位置不变。
- **文档版本对齐 0.10.3.20**：`README.md` 的下载入口、发行说明链接、ZIP 文件名与哈希命令、文档列表、macOS 段落，以及 `docs/windows-release-install.md` 全文，统一指向 `v0.10.3.20` / `ChatSheet-v0.10.3.20-win.zip` / `docs/releases/v0.10.3.20.md`；`README.md`「开发与测试」补上 `--agent-tool-tests` 与新入口 `scripts/verify-all.ps1`。
- **PaneHarness 版本断言改为读页面自身**：不再硬编码常量，改为从 `document.getElementById('app-version')` 读回 `dataset.version` 与 `textContent`，断言「四段版本无前缀且与 `data-version` 一致」。这样断言的是页面一致性，版本号再升级也不会误红。
- **仓库卫生**：清掉 `%SystemDrive%/`、`ChatSheet/component-staging/install.lock`、`NUL`、`.claude/` 四类残留，并在 `.gitignore` 追加一节规则覆盖「仓库根运行期残留」，已有的 `work/` 规则确认仍然生效。
- **统一验证脚本 `scripts/verify-all.ps1`**：一条命令依次跑 Release 构建、`--agent-tool-tests`、`--reliability-tests`、`--project-audit-tests`（`-SkipHost` 可跳过需要 Excel 的用例）和 `tests/web/*.test.mjs`，任一失败即非零退出，末尾汇总「通过 N，失败 M」并逐条列出失败项。
- **原生→文本切换补齐覆盖**：原生协议聊过几步后切到文本协议时，历史里仍留着 `tool_calls` 与 `role:"tool"`，而请求体已不再声明 `tools`，严格网关会直接拒。现在请求出口在 `IncludeTools == false` 时把原生工具痕迹降级成纯文本（助手调用拼进正文、工具消息转成普通 user 文本、Anthropic 的 `tool_use`/`tool_result` 块同理），并对历史对象做 clone，不改写 `Conversation` 里的原对象。mock 服务新增对应场景，端到端脚本可直接跑到这条路径。
