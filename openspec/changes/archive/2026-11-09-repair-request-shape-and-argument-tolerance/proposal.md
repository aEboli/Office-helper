# 修复请求结构配平、参数校验宽容度与验证链路

## Why

v0.10.3.19 的请求配平只覆盖了「部分配对」，最常走的「全部配上」分支反而把连续的工具结果整段放行，历史里混进一条不属于任何调用的结果就整轮 400。同一版本新增的参数校验比执行层更严：`offset` 写成字符串 `"0"`、`include_formulas` 写成 `null`（执行层本来当作未提供）都会被判 `ARG_INVALID`，模型换个写法重发才过，白烧一轮。此外三处边界没有被覆盖或记录：`excel_object` 缺 `root` 时先让用户点一次才报缺参；原生形态跑过几步后切到文本协议，历史里的 `tool_calls` 与 `role:"tool"` 会随请求重发而请求体已不声明 `tools`；源码、下载页与安装指南的版本号互相打架。

## What Changes

- 请求出口统一配平工具调用与结果：配不上的调用只留正文，配不上的结果整条丢弃；「全部配上」与「部分配对」两条分支按同一规则处理，历史对象不被就地改写。
- 参数校验对齐执行层的读取口径：非必填参数为 `null` 视为未提供；`integer`/`number`/`boolean` 接受可无损转换的字符串；数组与对象仍严格；必填项缺失仍报 `ARG_MISSING`。
- 声明为可空的布尔参数在 schema 上与之统一，避免目录文本、schema、校验与执行四处口径不一致。
- `excel_object` 缺 `root` 时先做非交互校验，再进入对象入口选择；补全后再完整校验一次。
- 请求不声明工具时，把历史里的原生工具痕迹降级为纯文本，四种协议一致，历史对象不改写。
- 版本号在程序集、面板、版本测试与文档中统一到同一版本，发行说明与安装指南同步更新。
- 面板版本断言改为读取页面自身声明，不再硬编码版本常量。
- 仓库根运行期残留纳入忽略规则。
- 新增一条命令跑完全部回归的统一入口。

## Capabilities

### Modified Capabilities

- `model-capability-fallback`：请求结构配平与工具痕迹降级属于该能力下「换协议不得丢保障」的延伸。
- `spreadsheet-operation-access`：参数校验宽容度与 `excel_object` 的校验顺序属于工具调用语义。
- `project-reliability`：配平、降级与统一验证入口属于可恢复性与可复核性。
- `windows-release-distribution`：版本一致性与发行说明的验证口径。

## Impact

涉及 `RequestBuilder`、`MessageRepair`、`ToolCatalog`、`AgentRunner`、测试与验证脚本、版本与文档。不改变审批策略、不改变工具清单、不改变撤销边界，也不放宽任何写操作的保护。
