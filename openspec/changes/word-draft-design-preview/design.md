# 设计

## 草稿与写入分阶段

- Word 面板中的起草、续写及生成式改写请求先返回草稿，不调用任何文档写入工具。该规则不受 `Automatic` 审批模式影响。
- 草稿卡展示真实结构预览，并提供“插入到文档”和“丢弃”操作。用户可继续用对话调整内容或视觉风格；调整只更新草稿，不修改 Word。
- 用户点击插入，或明确发出插入指令后，才进入写入流程。写入仍遵守当前审批策略和文档保护；只有快照能完整还原时才提供面板撤销。结构化草稿当前只保存文本快照，因此明确返回撤销不可用；`Automatic` 不能让生成轮跳过草稿确认。
- 明确的格式化、删除及内容完全由用户给定的精确替换仍走现有审批规则；本变更调整起草和模型改写文本的流程。
- 明确改写非空选区时，草稿记录“替换选区”作为候选目标，但只有用户在预览中确认替换才执行；选区外内容保持不变。

## 结构与设计

- 草稿采用有版本号的受限结构，不以任意 HTML 承载模型输出。首版块类型为标题、分级标题、正文段落、加粗/斜体文字、项目符号列表、编号列表、表格和引用段落。
- 预览按 Word 阅读层次呈现这些块，并提供跟随当前文档、简洁、商务、报告等风格选项。风格选项只影响草稿的层级、段落疏密和可用的强调样式；用户可用自然语言提出其他视觉调整。
- 插入器将块映射到 Word/WPS 的原生段落样式、列表和表格。正文不得包含 Markdown 标记、协议 JSON 或 HTML。
- 对当前宿主明确不支持的样式或目标，在写入前指出具体限制并拒绝操作；宿主转换在执行时失败则尝试恢复原文并读回，不能静默丢弃结构或声称已应用未验证的效果。

## 目标与状态校验

- 草稿关联生成时的文档身份，但不长期保存文档 COM 对象或活动 Range。
- 用户确认插入或替换时重新读取当前文档与选区。如果文档已经切换或原选区已变化，要求用户重新选择目标；如果选区非空且草稿没有明确替换意图，先询问插入或替换。
- 插入前显示文档名、目标范围和将写入的草稿预览。写入结果按 Word 工具实际读回报告；部分失败不得报告完整成功。
- 每个草稿有独立 ID 和状态。成功插入或丢弃后关闭该草稿；生成新稿不得静默覆盖尚未处理的草稿。

## 桥接边界

- 增加只创建/更新预览草稿的非写入通道，以及只在用户确认后执行的 `draft.insert` 桥接操作。
- 原生工具调用和 WorkBuddy 文本工具协议共用草稿校验、结构白名单和目标校验。
- `draft.insert` 在 Word/WPS UI 线程执行，复用现有写入快照和保护检测；不增加绕过现有审批的路径。

## 验证

- 起草和风格调整仅产生或更新预览，文档内容与格式保持不变。
- 用户确认前无写入调用；确认后目标、审批、保护和撤销可用性报告准确。
- 标题、列表、表格、强调和引用在预览与 Word/WPS 写入结果中保留语义；纯文本草稿仍能正确插入。
- 文档切换、非空选区、丢弃和重复点击均不会把草稿写入错误位置或重复写入。
- 两种工具协议对非法块和不支持能力给出一致、可见的结果。
